# Web：从首页到聊天的同一款轻聊

2026-10-27。本轮已落地 Web UI；沿用客户端 `QingliaoTheme.kt` 的橙色纸感方向，不修改原生界面或后端行为。

## 产品性格与共同语言

温暖、轻快、有一点俏皮的日常聊天空间。首页邀请人开口，登录承接邀请，联系人帮助找到人，聊天让内容安静地呈现，发现带来新的话题。

Web 与客户端共享纸色、暖墨色、杏色和操作橙的职责。亮橙只用作品牌装饰；发送等操作使用对比度更好的操作橙。
Web 色值在 `web/src/styles.css`；浅/深色与原生 `QingliaoPalette` 对齐。
少量蓝绿用于次要人物和兴趣标签，不表示未经确认的在线状态。

`BrandMark` 复用现有 logo；`paper-avatar`、`paper-bubble`、`paper-button` 为 Web 共同视觉原语。
首页演示与真实聊天使用相同的气泡基础样式，不再分别维护两套背景和圆角。
演示中的人物、对话和插画明确为虚构示意，不从真实聊天生成，不模拟真实在线人数。

## 已落地的五个入口

| 入口 | 变化 |
| --- | --- |
| Landing | 首屏“聊点小事，也聊点新鲜事”；朋友对话为主视觉，配一张吃面的小插画；主要操作为打开轻聊，次要操作滚动到下载区。 |
| 场景说明 | 三个可切换场景：熟人聊天、发现新话题、小助手检索整理。键盘方向键和 Home/End 可切换；不自动轮播。 |
| 登录及邮箱验证 | 同样的品牌、纸色、头像与气泡；表单保持单一主操作，补齐 label、密码管理器 autocomplete 和验证码语义；窄屏隐藏辅助演示。 |
| 联系人 | 顶部品牌与申请/设置；一句简短邀请；消息/联系人、搜索和列表按层级排列；发现固定在底部，不抢占主要任务。保留缓存先显示和后台校验。 |
| 聊天 | 收到的消息为纸色，自己为杏色；默认头像和会话标题一致；仅在确实在线时显示在线提示。取消历史气泡重复入场动画，保留虚拟列表、阅读锚点和草稿。 |
| 发现 | 品牌标题、简短邀请、轻量标签与兴趣点缀；继续保留找人、轻遇、今日一问、个人名片及原有权限流程。 |

动效只在首页对话进入视口时播放一次，切换场景仅作一次短过渡。按钮有短促按压反馈。
尊重 `prefers-reduced-motion`，不持续漂浮、不循环假装有人聊天；正文允许选择和复制。
新增文案同步中文、英文、日文；首页元信息和 PWA 启动背景也使用同一方向。
分享预览图由 `scripts/generate-favicons.cjs` 生成，同样使用纸色、朋友对话和新文案；不手工修改生成图片。

## Web 应该比客户端少什么

“简洁”先减少常驻入口和高级配置，不删掉基本沟通能力、数据同步或用户控制。

| 能力 | Web 的取舍 | 本轮状态 |
| --- | --- | --- |
| 私聊、群聊、最近历史、草稿、图片和文件 | 保留；浏览器会话中应能完成一次完整交流。 | 保留现有行为，未更改附件额度。 |
| 好友申请、资料、隐私、屏蔽、举报、退出登录 | 保留；这些是基本控制，不应为了简洁被删除。 | 保留。 |
| Agent 对话及额度查看 | 保留现有入口；额度与付费相关，不能藏掉使用限制。 | 保留；未把尚在方案阶段的交互卡片包装成已实现能力。 |
| 传输协议、网关、连接参数 | 日常设置不展示。诊断信息放技术文档；不能提供一个没有必要的协议选择器。 | 已移除设置中的 WebTransport 信息行，传输实现不变。 |
| 首页技术介绍与支持作者 | 不抢首屏；帮助与支持作者收在页脚。 | 已调整。 |
| 托盘、进程常驻、系统级通知及安装更新 | 客户端负责与系统整合；Web 不承诺关闭页面后持续在线。 | 原生已有托盘/更新入口；本轮未新增浏览器后台承诺。 |
| 本地历史目录、批量导入导出、服务器/模型/工具高级配置 | 建议放客户端或独立高级工作台，Web 主流程不增加同等入口。 | 产品边界建议，不声称这些功能都已在客户端实现；未删除既有独立 `/copilot` 路由。 |
| 开机启动、全局快捷键、深度系统集成 | 如后续建设，优先客户端，不在 Web 模拟。 | 后续方向，本轮不新增。 |

Web 仍需明确浏览器本地存储、设备、权限和在线状态的实际限制，不以“轻量”减少 ACK、持久化、账号隔离和错误提示。
发现是聊天的补充，保留一个底部入口与内部分页，不再增加独立的首页式功能矩阵。

## 验证与复查

在 `web/` 执行 `npm run build`、`npm test`，再运行以下隔离浏览器夹具，参数为本机 Chromium/Edge 可执行文件：

```text
node tests/product-ui-browser.cjs <browser>
node tests/contacts-browser.cjs <browser>
node tests/history-browser.cjs <browser>
node tests/social-browser.cjs <browser>
```

产品夹具覆盖三语言、浅/深色、1280/390/320 像素、场景键盘导航、减少动态效果、登录/注册字段及返回首页。
其他夹具验证联系人切换、未读和草稿、1200 条历史的虚拟列表与阅读位置、社交权限和移动端键盘布局。
截图位于忽略目录 `.gradle/product-ui/`；全部采用虚构数据和拦截的请求，不连接真实账号或线上消息。
构建与夹具不代替真实浏览器/手机、密码管理器、生产身份和网络联调。原生端本轮未改动，未重新构建。

本轮实际结果：Web 构建（含 TypeScript 检查）、85 项自动化测试与上述四组浏览器夹具通过。
联系人夹具额外检查深色设置选中项的文字对比度至少 4.5:1，以及设置中不再出现传输实现信息。

## 2026-10-28：安静的发送状态

成功不显示勾号或“已发送”标识。尚未确认的消息在前四秒保持安静，四至十秒在气泡侧边显示 12px 小圆圈；
十秒仍未收到 ACK 时改为红色感叹号，可点击重试。明确的本地写入错误或服务端拒绝仍立即提示失败。
手动重试重新计时，保留原 messageId、引用和附件信息；自动重发不重置这段展示时间，避免提示反复消失。

`MessageSendIndicator.vue` 只为当前可见的待发消息安排阶段切换定时器；成功或卸载后清理，不新增全列表轮询。
展示超时不代表服务端一定未接收，不删除 outbox，也不改变后台重发周期。迟到的匹配成功 ACK 仍能消除失败提示。
`messageSendState.ts` 维护四秒/十秒边界，`sendStartedAt` 仅在用户手动重试时更新，不改消息原始时间或排序。

验证：Web 构建、89 项自动化测试通过；联系人浏览器夹具通过真实计时验证安静阶段、小圆圈、失败、手动重试、
outbox 保留及迟到 ACK 清除。使用拦截的远程请求，没有连接线上服务。

## 2026-10-28：减少模板感

上一轮通用放射星形、堆叠头像、悬浮注释、连续圆角卡片与抒情文案叠加，容易形成通用 AI 产品页的观感。
通用星形还容易被误认作其他品牌。本轮移除首页、登录、聊天空态与分享图中的全部星形装饰，不再建立平行品牌标记。

保留原有轻聊 logo、纸色、操作橙和真实聊天使用的气泡样式，把识别度集中在这些已有元素。
首页标题回到墨色，橙色用于操作和少量章节标识；取消堆叠虚构头像与悬浮装饰，不制造用户规模或活跃度暗示。
场景按编号、细线和文字层次排列，下载入口使用开放的文字行；结尾保留“下一句，留给你”，移除背景色块和顶部图标。

场景内容应决定展示形式。首屏保留朋友吃面的对话和小插画；中段默认展示今日一问的两条回答，
不再把发现功能也画成另一个私聊框。`DailyQuestionPreview.vue` 只展示虚构示例，不模拟可提交的表单。
登录说明及聊天空态使用明确的操作说明，减少重复的情绪化短句。中英日文同步。

后续设计继续遵循三条取舍：优先具体的人与事情；用排版建立主次；新增装饰必须有轻聊自己的含义。
照片和插画应围绕真实的生活场景形成统一系列，避免为了填满留白不断添加无关符号。

本轮验证：Web 构建、89 项测试、产品页/登录三语言浅深色与窄屏浏览器夹具、1200 条历史阅读位置回归通过。
原生端和后端未改动；截图使用虚构数据，不代表线上联调。
