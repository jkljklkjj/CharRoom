# 本地历史读取与删除优化（2026-10-28）

本轮接续 [消息更新、内存与轮询优化](CLIENT-PERFORMANCE-SECOND-PASS.md)，只调整本地历史存储路径，不改变协议、历史文件格式或 IndexedDB schema 版本。

## 原生：桌面、CLI、Android

共享 `core/IndexedHistoryJournal.kt` 的改进：

- 单会话分页和时间范围读取在一次调用内复用一个文件句柄，逐条校验 CRC；空结果不打开正文读取句柄。压缩时也复用源文件句柄，并在原子替换前关闭它。
- 有效记录体积随索引插入、覆盖和删除增量更新，压缩门槛判断为常数时间；不再每追加一批消息就遍历所有历史索引求和。重载索引时重建统计，压缩触发门槛保持原样。
- 时间范围查询从 TreeMap 的下界开始，遇到超过上界的记录即停止。索引已加载时，索引定位和遍历为 `O(log N + K)`，其中 K 为匹配记录数；首次加载仍需要读取文件索引。
- 跨会话分页使用有界最小堆，只保留 `skip + pageSize` 个最佳候选引用，不再收集每个会话的候选后进行全量排序。候选引用空间由 `O(会话数 × 请求深度)` 收敛到 `O(请求深度)`；这不包含既有的文件索引缓存，也不意味着深分页内存与页码无关。
- 最终选中记录按文件分组读取，每个文件只打开一次正文句柄；读取前在对应 journal 锁内重新按 ID 定位，避免并发压缩后使用失效偏移。排序仍为时间倒序、ID 倒序；完全相同的键保持原文件顺序。

原生三个入口共同使用该实现，因此不需要另写 Android 版本。Web 已使用 IndexedDB 时间索引分页，无需复制原生文件读取算法。

## Web：IndexedDB

`utils/messageDB.ts` 的改进：

- 单条删除使用账号、会话、消息 ID 的精确索引及 key cursor，避免扫描和反序列化整个会话。索引非唯一，因此同 ID 重复行全部删除，不影响其他账号或同号群聊。
- 清空会话和清空账号也使用 key cursor，只读取删除所需的主键。
- 清空会话的消息与摘要放在同一事务。以前先删消息再开启事务删摘要，事务间到达的新消息可能保留正文却失去新摘要；现在后续写入完整保留，失败时一起回滚。同步游标语义保持原样。

原生会话删除已在 journal 的同步边界内完成，未采用 Web 的两事务删除流程；无需添加相同修复。

## 验证范围

新增回归覆盖时间范围端点、相同时间多 ID、最大时间值、范围外损坏正文不被解码、跨会话分页排序与群聊隔离，以及 Web 精确删除、重复行、账号隔离、清空期间新消息和事务回滚。

Web 严格类型检查、生产构建和 **110 项单测通过**；浏览器 1200 条分页历史、阅读锚点、会话切换恢复及移动布局回归通过。删除路径测试先确认旧实现会打开正文游标，修复后只打开精确索引的 key cursor；并发清空测试也先复现了“正文仍在、新摘要丢失”。

原生编译、**97 项 JVM 测试**及 Android Kotlin 编译、**5 项单测通过**；覆盖大批删除后的压缩与重新打开后的追加。命令跳过 `buildQuicNative`，没有生成 APK、构建 JNI 或装机验证。

测试使用临时文件、fake IndexedDB 和浏览器隔离夹具，不连接真实账号或服务；未做真实磁盘吞吐、堆或真机性能采样。本轮未修改后端、协议，也未提交或推送。
