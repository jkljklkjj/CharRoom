# 消息更新、内存与轮询优化（2026-10-28）

本轮接续 [第一轮性能改进](CLIENT-PERFORMANCE-2026-10-28.md) 和 [会话标识](CONVERSATION-IDENTITY.md)，同步评估 Web、桌面、Android。

## 六项改进

1. **原生 Agent 累计全文替换。** 分发器输出累计全文，ViewModel 经 `ConflatedStreamUpdates` 按请求 ID 合并约 16ms 内的快照，再调用 `ChatState.applyAgentSnapshot` 替换内容。`A → AB` 最终为 `AB`，不再追加成 `AAB`。终态不会被晚到普通快照覆盖，完成标记只保留有上限的 ID 集合。Web 保留已有按动画帧合并的全文替换。传输接收端的终态落库及 ACK 边界保持不变。
2. **原生历史只排队未提交变更。** `ChatState` 收集发生变化的消息，ViewModel 将其移交 `HistoryWriteQueue`，按 ID 合并最新修订；写入成功后释放队列持有的正文。不再为每次变更复制两个全局列表，也不保留整个登录期间的 `savedPrivate/savedGroups` 完整正文。已落库的历史补拉不重复入写队列；旧页导入显式入队。磁盘失败沿用有界重试和 flush 失败反馈，未提交数据仍保留，不靠淘汰来伪装写入成功。删除先等待旧写入提交，防止排队副本重新写回已删除内容。ACK 别名归并继续由既有持久层处理。
3. **原生摘要增量维护。** 会话摘要包含最多 60 字符的正文片段、显示时间、发送方和消息 ID，在消息变化时更新。联系人行只格式化其对应摘要，不订阅全局消息列表，不再为每个联系人扫描私聊与群聊。最新消息删除后回退到缓存中的上一条摘要。Web 继续使用既有独立会话元数据。
4. **限制显示数据总量。** 原生 `ConversationCacheBudget` 为会话桶设置总计 4000 条、2000000 正文字符预算，按最近访问淘汰非活跃桶的数据，保留 StateFlow 身份。当前选择及有订阅者的会话受保护，重新选择空桶时从本地历史补回；跨桶淘汰由统一消息变更互斥边界保护。Web 当前历史窗口最多 2000 条、2000000 文本/URL 字符；向上阅读保留旧端，跟随最新时保留新端。窗口截断后显示“查看最新消息”，从 IndexedDB 重读最新页，旧数据及 outbox 不删除。
5. **Web 补拉仅合并已提交批次。** `restoreHistoryPage` 将批次及游标提交到原有 IndexedDB 事务后，直接归并这批消息，不再按“已加载条数 + 批次条数”读取整个窗口。仅当最旧显示消息改变时，按消息 ID 索引查询一个分页边界。加载更早页面时恢复消息锚点，不能以总高度差推断窗口截断后的阅读位置。
6. **业务轮询感知状态与前后台。** Web 与原生轻遇活跃/匹配状态使用约 1.2 秒间隔，空闲状态 15 秒；失败从 4 秒指数退避到最多 60 秒。Web 页面隐藏或离线停止安排查询，恢复可见/联网时立即校验，并避免并发 GET。原生订阅 `AppActivity`：Android 绑定 Activity 生命周期，桌面绑定窗口显示及最小化状态；恢复前台、进入轻遇立即查询，操作完成后唤醒轮询。Web 好友申请后台跳过、请求合并，前台/联网恢复补查。实时传输心跳不采用业务轮询调度。

## 内存与持久性边界

- 字符预算是字符数，不是 JVM 堆字节或浏览器进程内存。原生两份全局镜像仍各最多 200 条；摘要和空桶 Flow 控制对象独立保留，供联系人展示和稳定订阅使用。
- 原生活跃订阅可能临时超出桶预算；后续消息变更继续淘汰非活跃数据。未提交写入队列不能按缓存策略丢弃，磁盘持续失败时需处理写入错误。
- Web 单条超大消息和未结束的 Agent 流快照受保护；终态提交后重新收敛窗口。普通历史与已提交消息按窗口预算裁剪。窗口不是历史存储上限。
- 削减内存不会推进 seqId。游标仍只代表已提交的历史区间，发送 ACK 不能充当完整历史同步证明。账号切换、视图代次和本地写入失败检查继续保留。
- 原生 ACK/删除可查找仍保留在会话桶中的消息，即使它已移出全局镜像；避免活跃会话在其他会话大量收信后失去状态更新。

## 实际验证

- Web：构建、严格类型检查及 **107 项测试通过**。新增覆盖窗口条数/字符预算、20 批补拉不重读全窗口、回到最新、索引分页边界、前后台与离线恢复、轮询退避。
- 浏览器：2600 条持久历史、2000 条活动窗口、继续加载旧页和回到最新通过；原有 1200 条长消息阅读锚点、切换缓存及移动布局通过。
- 浏览器：5000 联系人、同号私聊/群聊、延迟 ACK/outbox、社交双账号/匹配生命周期及草稿回归通过。所有响应均为隔离夹具。
- 桌面/CLI：编译与 **94 项 JVM 测试通过**；覆盖累计文本替换、终态晚到数据、脏消息排队/释放、6000 次跨会话写入后的缓存预算与稳定 Flow、全局镜像之外的 ACK、摘要保留和删除回退。
- Android：Kotlin 编译与 **5 项单元测试通过**；命令跳过 `buildQuicNative`，没有构建 JNI、生成 APK 或装机验证。
- 未进行真实服务联调、设备电量测量或堆分析，不能由以上测试推算帧率或耗电改善百分比。没有修改后端/协议，没有提交或推送。
