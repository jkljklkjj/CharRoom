# 历史空操作与整批校验（2026-10-30）

接续 [历史批处理与 PR 检查](HISTORY-BATCH-AND-CI.md)，本轮只改共享 `IndexedHistoryJournal` 及其测试；桌面、CLI、Android 使用同一份源码。

## 已复现的问题

- 删除从未存在的 ID 会创建一个只有头部的 `.history` 文件。
- 重复保存相同的历史或别名，即使没有追加记录，仍打开写句柄并调用磁盘同步。
- 在批内逐条验证参数；后一条的 ID 不合法时，前面的合法行已经追加。调用者收到异常，但重新打开文件后可能读到该行。

新增行为测试先复现前两类可观察状态问题，再实现优化。磁盘同步计数测试在实际 FileDescriptor 同步边界统计调用，未替换真实落盘行为。

## 当前实现

1. 打开文件前检查所有输入的 ID 和 UTF-8 正文大小；同 ID 在一批内保留最后一个值。无效输入不会修改原文件。
2. 对可能相同的记录，共用一个只读句柄比较正文。正文或时间变化才进入写入；缺失 ID 的删除不产生记录。
3. 没有变化且没有待修复尾部时，直接返回，不开写句柄、不创建文件、不调用同步。实际变化仍逐批同步后返回。
4. 不完整尾部仍必须截断并同步修复，即使本次提交的有效正文没有变化。journal 格式、CRC、压缩、账号/会话隔离和 ACK 语义保持原样。

整批预检查只保证参数校验失败前不写文件，并未把整个 append 批次改造成数据库事务；写入期间断电、磁盘故障和同步失败仍沿用现有恢复语义。预编码的 UTF-8 数据暂存在本批内，内存开销随批大小增长；没有新增无限缓存。

## 验证

- 新增 4 项：非法后续行不产生前序行；缺失 ID 删除不创建文件；相同批次不额外同步；空操作修复残尾及同 ID 最终值保持。
- 同步计数用例写入 100 条后重复保存 10 次：初次同步 1 次，重复保存增加 0 次；随后修改两条记录的批次再同步 1 次。这是调用次数证据，不是吞吐或时延基准。
- JVM 全量 134 项、CLI 28 项通过，CLI headless runtime 检查通过。
- Android Kotlin 编译和 5 项 Debug 单测通过，跳过 JNI 构建。没有执行安装、真机磁盘性能或网络收发验证。
- 双 proto 四处副本检查通过，本轮没有修改协议或 API 字段。

Web 使用 IndexedDB 事务，不直接调用本地文件同步；无需复制本轮文件算法。本轮未修改 Web，也未重复其构建与浏览器测试。深分页游标与别名删除生命周期仍是独立后续项。
