# Web 本地优先加载

2026-10-27。覆盖 Web 与后端联系人快照接口；原生客户端本轮不改动。

## 展示与同步顺序

认证确认账号后，`ContactDirectorySync` 从按账号存储的 IndexedDB 快照恢复联系人、群组及本地会话预览，
再后台校验版本。登录启动、侧栏挂载、页面回到前台、网络恢复、实时连接认证完成共用同一同步入口。
同一登录会话的并发请求合并，成功校验后十五秒内的自动触发合并；前台每分钟额外校验一次。
不会在打开某个联系人时重新全量拉取整个列表，也不先清空现有列表再刷新。

首次无快照显示骨架；有快照显示旧数据并提示同步；同步失败保留数据并提供重试；确认无成员才显示空状态。
关系变化后用完整的新快照替换成员集合，能够删除已不在服务端列表中的用户或群组。
按 ID 复用未变化的记录，在线状态由实时状态接口维护，不持久化成永久“在线”。

联系人变化的本地操作、服务端好友接受通知会触发重新校验；断线丢失的通知由重连、前台恢复和周期校验补偿。
当前没有完整的关系变更日志，不声称所有后台变化即时推送；最迟在下一次成功校验时更新。
缓存不作为查看权限或发送权限的凭据，授权继续由服务端检查。

## 后端条件快照

`GET /api/contacts/snapshot?version=<opaque-version>`，用户来自认证上下文。

- 版本未变：`{version, unchanged:true}`，不返回用户/群组列表，也不读取完整资料。
- 版本变化或首次读取：`{version, unchanged:false, users:[...], groups:[...]}`。
- 响应 `Cache-Control: private, no-store`；浏览器的本地账号缓存显式管理，不交给公共 HTTP/PWA 缓存。

校验读取 Mongo 的 friends/groups/contactsRevision 投影，再批量读取 MySQL 的 id/directory_version，
不是每次查询完整资料后才计算哈希。好友关系和群成员变更在同一 Mongo 更新中递增关系 revision；
用户名、签名和头像写入在同一 SQL 中递增资料版本。成员 ID、成员存在性、资料版本与账号共同形成版本摘要。

完整读取前后再次核对版本，遇到并发修改最多重试三次，不能把混合快照标记成已同步的新版本。
SQL/Mongo 没有跨库事务，此方法提供可重试的稳定快照检查，不宣称跨库原子提交。

头像使用签名链接时，客户端会在临近到期时请求完整快照，后端重新签名；不依赖用户修改资料来刷新过期 URL。

**部署前置条件：**执行后端 Flyway `V2__contact_directory_versions.sql`，为 users 和 groups 增加
directory_version。不要跳过迁移直接部署新版写入语句。后续新增群资料更新 SQL 时，也必须同时递增版本。
直接在数据库手工修改展示字段而不更新版本不在此同步契约内。

## 消息页面与阅读位置

`ConversationViews` 保留最近十个会话的已加载页面和分页游标，上限一万条消息、两百万字符的正文/URL。
超过任一预算按最近访问顺序淘汰；不截断正在展示的页面，不删除 IndexedDB 历史。
超出整个预算的大页面不留在内存，返回该会话时从本地最近一页恢复。

切换回仍在内存中的会话立即展示，不重复读取最近一页；首次进入则异步读 IndexedDB，并保持独立加载/失败状态。
读取期间收到实时消息时按 ID 合并，不能由迟到的本地页覆盖新消息。隐藏会话的缓存同步接收实时增量、状态和 ID 确认。
Agent 流更新也按所属会话处理，不能写进当前打开的其他聊天。

阅读位置记录消息锚点、像素偏移、锚点高度和是否在底部。锚点高度用于避免长消息内部的偏移超过默认估算高度。
虚拟列表重建或移动/桌面布局切换后恢复锚点，
后续测量消息高度时继续修正位置；用户在上方阅读时不强制跳到底部。内存页面已淘汰、原锚点不在新页面时不保证恢复该旧位置。
账号或登录代次变化清空内存视图，旧异步任务不能更新新会话。

## 持久化与游标

Web 消息库版本提升为 7，增加按账号和服务端 conversationId 保存的 sync_cursors。
增量补拉将消息、会话元数据、已应用游标放在同一个 IndexedDB 事务中，事务失败一起回滚。
内存游标只能在该事务成功后推进，旧 localStorage 游标不再作为已落库依据。
登录时从 IndexedDB 恢复已应用游标；七天窗口恢复不会擅自推进增量游标。

版本 8 增加 `message_id_aliases`：ACK 是唯一同时出现客户端 ID 与服务端主键的位置，
因此别名在确认事务里先落库，之后所有写入（追加、历史合并）和读取都按它归一，
`local_` 占位行只要被服务端行取代就按身份回收，不再依赖文本和时间窗。
别名按账号和会话隔离，退出登录时随消息一起清除。

本地消息加载、后台同步、空记录和失败分别展示。多个同步任务共享计数，旧登录代次的任务结束不能清掉新任务的状态。
加载缓存不跳过现有登录身份校验；本轮没有新增离线登录或本地 JWT 验证功能。

## 验证

隔离测试覆盖缓存先显示、刷新合并、未变化不重建、删除同步、账号隔离、迟到结果和并发修改，
以及消息页读取竞争、LRU 上限、阅读锚点、隐藏会话增量、游标事务回滚与重启恢复。
浏览器夹具验证暖启动在延迟的网络校验完成前显示缓存，并只发一个校验请求；历史夹具验证 1200 条已加载消息切换返回后恢复位置。
本轮 Web 构建、85 项单元/集成测试、联系人/历史/社交三组浏览器夹具通过；后端相关 35 项测试通过。
历史夹具覆盖长消息内部位置恢复。ast-grep 阻断规则通过，仍报告两条原有 ACK 提示。
构建/夹具不等于真实 MySQL/Mongo 多节点故障联调；迁移尚未在实际数据库执行。

| 数据 | 缓存位置与上限 | 使用与失效 |

`SocialViewCache` 的范围包括账号和登录代次，读写使用失效代次标记。过期、资料修改、申请好友、屏蔽/解除屏蔽、
回答发布/删除、交换名片和联系人关系通知会使对应快照失效；旧请求不能重新填入失效后的缓存。
缓存读写复制数据，组件就地修改关系和表单不会污染复用快照。体积超限时不保留，淘汰不删除服务器数据。
这些页面数据不进入公共 HTTP/PWA 缓存，也不将他人的名片和回答长期落盘。

本人快照只用于先展示；从缓存恢复时，编辑按钮等待权威资料刷新，失败时保留快照并提供重试。
屏蔽名单始终实时读取，不作为本人资料快照的一部分持久化。第三方名片仍实时获取，操作权限仍由后端裁决。

回答发布绑定提交时的草稿修订 ID。响应只清除该修订；发布时继续输入、输入改回同样文字、刷新后的更新草稿都不会
被旧提交删除。刷新问题列表前检查输入版本，迟到的 GET 也不能覆盖正在写的内容。
退出登录清理该账号的本人快照及回答草稿，并清空会话内存缓存；旧代次的组件卸载不能把内容写回。
浏览器存储不可用时仍可编辑和联网提交，无法承诺刷新后恢复；关闭弹层、跨页导航不等于离线发布。

余额/订单、认证结果、临时匹配房状态继续实时读取。缓存用于缩短等待，不把这些状态当成适合长期展示的静态资料。
头像和附件继续使用浏览器已有 HTTP 机制，不额外复制一份私有媒体到公共 Service Worker 缓存。

本轮单测覆盖 TTL、北京时间换日、LRU/大小上限、账号与代次隔离、失效后的晚到写入、不可变快照、
本人资料串号/过期、草稿修订及 API 成功/失败时的失效语义。浏览器夹具覆盖关闭重开、筛选/位置恢复、
完整刷新及防抖未到期时刷新、双账号草稿隔离、本人名片延迟刷新与发布期间编辑。

本轮实际结果：Web 构建、97 项自动化测试通过；社交、联系人（含延迟 ACK）和 1200 条历史阅读位置浏览器夹具通过。
所有远程响应均为隔离夹具；没有改动后端或原生客户端，没有进行线上联调或推送。

## 2026-10-28：原生客户端补齐发现页缓存

上一节记录的是 Web 实施；本节补齐桌面与 Android 的共享实现，不代表两端复用同一运行时。
`core/SocialLocalCache.kt` 管理账号和登录代次，`SocialViewModel` 协调加载，`SocialScreen` 恢复筛选及列表索引/像素偏移。
CLI 没有社交页面，本轮没有对应交互改动。

- 发现列表缓存最多 8 份筛选结果，合计不超过 250000 个序列化字符；今日一问单独最多 250000 字符。
  两者均使用固定 20 秒有效期，读取不续期；当日问题跨北京时间零点失效。关闭重开页面可复用已加载分页，超限页面不缓存。
- 本人名片按账号落盘，最长 24 小时；先展示快照，再并行获取权威资料与屏蔽列表。刷新成功前不能编辑，失败时可重试。
  他人资料、屏蔽名单及发现列表不落盘。资料与关系修改、发布回答及交换名片成功后使页面缓存失效；失效前的查询不能回填。
- 今日一问草稿按账号和北京时间日期保存，最多 500 字，包括尚未提交的空内容。
  输入即更新会话内存，250ms 防抖后在 IO 线程原子落盘，关闭页面补存；重开页面可在磁盘写入前恢复会话草稿。
  提交仅清除对应修订，防止旧提交或延迟写入覆盖新输入。进程被强制终止前尚未落盘的输入不保证恢复。
- 桌面文件位于用户目录的 `.charroom/social/`；Android 使用应用私有 `filesDir/social/`，由 `ChatApplication` 安装。
  退出登录清除该会话的本人名片和草稿，并使旧会话失效；旧请求和卸载补存不能重新写入。账号切换保留各自独立磁盘文件。

与 Web 的共同业务语义已同步；存储介质分别使用 JVM 文件和浏览器存储，滚动位置分别使用 Compose 列表位置与 Web 消息/元素锚点。
本轮不改动后端及 Web，不新增旧格式迁移或离线认证能力。

实际验证：桌面/CLI 共享源码 `:compileKotlin` 通过；9 项 `SocialLocalCacheTest` 和 4 项 `SocialContractTest` 通过。
Android `:androidApp:compileDebugKotlin -x buildQuicNative` 通过，明确跳过 JNI 原生构建；未生成 APK、未做装机交互或真实服务联调。
同账号因 token 刷新重建页面时复用会话草稿；账号切换或退出后旧会话失效，这两类生命周期不混用。
