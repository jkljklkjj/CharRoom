# 历史深页的有界多路归并（2026-10-30）

## 适用路径

`IndexedHistoryJournal.page(directory, group, page, size)` 跨多个会话读取一页。每个会话已经有按时间和 ID 排序的 TreeMap 索引。原实现逐个会话取候选，保留最好的 `skip + size` 个引用，再排序、跳过前面的记录。

现在对第二页及更深、且会话文件数不超过 64 的请求采用多路归并：每个非空会话在堆中只放下一条引用，弹出后补该会话的前一条；跳过的引用直接丢弃，最后只保留所需页。正文仍在最终选择后按文件批量读取，CRC 和压缩后 ID 重定位保持原样。

浅页沿用原有 top-k 选择；超过 64 个会话也保留原路径。归并会同时持有各来源的 journal，强行对大量会话启用，可能扩大活跃索引内存或引起索引反复加载。这里限制来源数量，避免只优化堆却忽略它背后的索引成本。

## 成本和边界

归并路径候选引用空间为 `O(会话数 + 页大小)`，原选择路径为 `O(skip + 页大小)`。例如 18 个会话、跳过 50,000 条、取 50 条，归并堆最多 18 条候选，结果页最多 50 条；旧候选上限为 50,050 条。这是数据结构上限推导，不是实测堆占用或时延结论，也不包括已有 journal 索引内存。

每个来源首次访问时加载索引；继续向前使用 TreeMap 的 `lowerEntry`，不对每条跳过记录执行文件 stat。跨会话深页仍须跳过前序记录，未实现全局跨请求游标。后续单会话新增 `pageBefore` 并接入聊天页，旧 `page(skip, limit)` 保持兼容，见 [游标、预算与提交](HISTORY-CURSOR-BUDGET-COMMIT.md)。

排序为时间倒序、ID 倒序；完全相同的键保持原文件来源顺序。每次索引操作在 journal 锁内，但整个跨会话读取不是事务快照。并发写入、删除和压缩仍沿用原有非快照语义，正文读取前重新按 ID 定位。

## 验证与跨端结论

新增 2 项覆盖：18 个会话中的重复键、空文件、深页及越界页与全量稳定排序一致；80 个会话超过阈值时原选择路径排序保持。连同既有边界、CRC、压缩、写入故障等回归，JVM 全量 136 项、CLI 28 项通过；Android Kotlin 编译及 5 项单测通过，跳过 JNI 构建。

共享实现供桌面、CLI、Android 使用；Web 已使用 IndexedDB 索引游标，不需要移植文件归并。本轮未修改 Web、协议或文件格式；未运行真机、完整 APK、端到端联调或性能压测。
