# Web 联系人搜索与名片（2026-10-29）

## 最终行为

- 已有联系人/消息在本地即时过滤，不消耗远程搜索额度；只匹配昵称（含群名/备注名），账号和数字 ID 不再参与模糊匹配。
- 联系人页停止输入3秒后自动请求 `/users/search`；Enter、手机键盘“搜索”和页面搜索按钮通过同一个表单立即提交并取消待执行的延迟任务，不跳转或刷新页面。手机提交后收起输入焦点。
- 远程结果默认第一页（每页6条），滚动到距底部200px内自动请求下一页；列表不足一屏时用底部“加载更多”按钮兜底。最多4页/24条，第4页或整页不足6条即停止，每页请求都计入8次额度。
- 自动和手动远程搜索共用每账号滚动60秒8次额度。浏览器预算跨侧栏重新挂载保留；后端Redis按已认证账号权威裁决，覆盖多标签、刷新、设备和token轮换。客户端额度不作为安全控制。
- 第9次不继续发请求，显示剩余秒数；服务器429/5001读取 `data.retryAfterSeconds`（或Retry-After），只等待冷却，不清除登录。额度恢复后可以再次提交，不自动重放冷却期间的请求。
- 中文输入法组合期间不搜索；旧请求即使迟到也不能替换新关键词/新账号结果。空查询和消息页不发起远程搜人。

入口：`components/SidebarUsers.vue`、`services/contactSearchBudget.ts`、`api/index.ts`；后端契约见相邻仓库 `chat-room/docs/development/USER-SEARCH.md`。不会改变握手限流。

## 名片呈现

`SocialProfileCard.vue` 和 `styles/social.css` 调整封面纹理、头像重叠位置、昵称和关系标签、账号/城市信息、签名分隔和内容块。保留纸色/橙色主题，标签使用既有浅绿变量，浅深主题共享同一结构。展示卡中不放交互控件，编辑/加好友/隐私操作仍在独立区域。

城市移至顶部信息行后仍由detailsVisible控制；陌生人预览不能额外看到城市。昵称/简介/兴趣保留换行与长文本折行，320像素不横向溢出。没有新增图片下载或动画依赖。

## 跨端评估

桌面/CLI/Android没有HTML表单或Web名片CSS，原生通讯录仍使用本地文本过滤；原生社交搜索已有ImeAction.Search处理。当前原生没有调用 `/users/search` 的同名路径，后端此入口新限制不改变其他查询接口。无需同步Kotlin代码，未运行原生构建；通用搜索/关系权限与消息协议不变。
