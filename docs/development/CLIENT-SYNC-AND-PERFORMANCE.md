# 客户端同步与历史性能优化

本轮修改 Web 和桌面文件存储，协议、后端存储和 Android 实现不变。

## 同步与生命周期

`web/src/services/conversationSync.ts` 按登录版本和会话合并补拉请求，处理全部 `hasMore` 页面。先校验顺序和返回游标，再等待 `restoreHistoryPage` 的 IndexedDB 事务完成，最后更新该会话游标。失败保留上一个已落库的游标；空响应不推进。seq 使用十进制字符串和 BigInt，拒绝超出安全整数范围的 number。

实时消息和发送 ACK 只触发权威补拉，不直接推进完整历史游标。传输层的同步提示只分发一次。消息收到、网络写入、发送 ACK、历史已完整落库仍是不同状态。

本地 seq 游标改用带 `version: 2` 的数据。旧版可能由 ACK 或提示直接推进的裸游标不再恢复，首次使用时从可靠起点重新补拉；消息按 ID 去重，已有本地历史保留。长会话可能产生一次额外补拉成本。

`sessionEpoch.ts` 在登录、退出和页面销毁时取消旧请求，重新登录同一账号也创建新版本。`http.ts` 按版本合并 token 刷新，忽略旧响应，认证请求具有 20 秒截止时间。页面请求可以额外传入 AbortSignal。会话加载另有视图版本，防止 A→B→A 的延迟读取覆盖当前内容，同视图的历史翻页请求也会合并。

`sessionBootstrap.ts` 立即启动连接，将好友、群组、通知和历史恢复独立加载。好友在线状态依赖好友列表；其他任务失败不会阻断聊天入口。每个异步状态写入仍需检查其所属版本。

## 本地历史和渲染

IndexedDB 升级到 v6，保留已有消息 ID 索引和旧行键分配索引，新增账号、会话、时间、排序 ID、行键的复合索引。升级事务补齐已有行的排序字段。分页使用稳定联合游标，补入旧历史不会重新编号已有行。

历史页仅按消息 ID 批量查找并更新传入记录，不全量读取、删除和重写会话。已有本地状态优先保留；事务提交失败向上传播。选中会话刷新时保留已加载的历史范围。

`VirtualMessageList.vue` 使用前缀高度、二分查找和有限预渲染区间，只挂载视口附近的行。ResizeObserver 记录可变行高；插入旧历史、图片或文本改变高度时保持可见消息锚点，底部阅读时继续跟随底部。移除前后台切换时直接裁掉历史数组的行为，避免与分页游标冲突。

桌面 `AtomicHistoryFile.kt` 在目标目录写临时文件、同步文件内容、关闭文件，再执行原子替换。写入失败保留原文件，清理临时文件；不支持原子替换时报告失败，不降级为截断写入。历史、删除后的会话、seq 文件和待发文件均使用此入口。文件格式保持兼容，仍然存在整文件解析和重写成本；这轮没有迁移 SQLite。

## 验证与边界

2026-10-27：Web 47 项隔离测试、类型检查和构建通过；下述三套浏览器夹具回归通过。JVM 编译和两项指定存储测试通过。本轮没有修改后端代码。

Web 离线回归运行 `npm test`，构建运行 `npm run build`（包含类型检查）。覆盖多页补拉、请求合并、落库失败、账号和视图切换、迟到的 token 刷新、ACK 不推进游标、同步提示只分发一次、旧连接解码隔离、旧 schema 迁移和稳定分页。

构建后使用本机 Chromium 运行以下脚本，全部 API/传输由隔离夹具代替：

```text
node tests/history-browser.cjs <Chromium executable>
node tests/contacts-browser.cjs <Chromium executable>
node tests/social-browser.cjs <Chromium executable>
```

历史浏览器回归覆盖 1200 条分页历史、连续翻页、少于 50 个挂载行、底部跳转、可变高度锚点和移动端调整。该节点数量是夹具断言，不是生产性能指标。

桌面使用 `scripts/gradle-windows.ps1 test --tests core.AtomicHistoryFileTest --tests core.RecentHistoryStorageTest --no-daemon`，覆盖部分写入失败保留旧文件，以及 650 条历史合并、恢复、删除和账号隔离。

未做真实服务的多设备联调、网络故障注入、生产负载测试或 Android 构建。客户端只承诺提交服务端响应后再推进游标；后端异步持久化造成的不可见消息、永久 seq 空洞和完整性水位仍需服务端契约进一步解决。本轮没有重构 outbox 的发送确认与重试语义。文件同步和原子替换也不代表完成了断电恢复验证。
