# 客户端同步与历史性能优化

本文记录当前客户端同步、消息身份与历史存储约定；覆盖 Web、桌面和 Android。

## 同步与生命周期

`web/src/services/conversationSync.ts` 按登录版本和会话合并补拉请求，处理全部 `hasMore` 页面。先校验顺序和返回游标，再等待 `restoreHistoryPage` 的 IndexedDB 事务完成，最后更新该会话游标。失败保留上一个已落库的游标；空响应不推进。seq 使用十进制字符串和 BigInt，拒绝超出安全整数范围的 number。

实时消息和发送 ACK 只触发权威补拉，不直接推进完整历史游标。传输层的同步提示只分发一次。消息收到、网络写入、发送 ACK、历史已完整落库仍是不同状态。

本地 seq 游标改用带 `version: 2` 的数据。旧版可能由 ACK 或提示直接推进的裸游标不再恢复，首次使用时从可靠起点重新补拉；消息按 ID 去重，已有本地历史保留。长会话可能产生一次额外补拉成本。

`sessionEpoch.ts` 在登录、退出和页面销毁时取消旧请求，重新登录同一账号也创建新版本。`http.ts` 按版本合并 token 刷新，忽略旧响应，认证请求具有 20 秒截止时间。页面请求可以额外传入 AbortSignal。会话加载另有视图版本，防止 A→B→A 的延迟读取覆盖当前内容，同视图的历史翻页请求也会合并。

`sessionBootstrap.ts` 立即启动连接，将好友、群组、通知和历史恢复独立加载。好友在线状态依赖好友列表；其他任务失败不会阻断聊天入口。每个异步状态写入仍需检查其所属版本。

## 本地历史和渲染

IndexedDB 升级到 v6，保留已有消息 ID 索引和旧行键分配索引，新增账号、会话、时间、排序 ID、行键的复合索引。升级事务补齐已有行的排序字段。分页使用稳定联合游标，补入旧历史不会重新编号已有行。

历史页仅按消息 ID 批量查找并更新传入记录，不全量读取、删除和重写会话。已有本地状态优先保留；事务提交失败向上传播。选中会话刷新时保留已加载的历史范围。

`VirtualMessageList.vue` 使用前缀高度、二分查找和有限预渲染区间，只挂载视口附近的行。ResizeObserver 记录可变行高；插入旧历史、图片或文本改变高度时保持可见消息锚点，底部阅读时继续跟随底部。移除前后台切换时直接裁掉历史数组的行为，避免与分页游标冲突。

共享 `AtomicHistoryFile.kt` 用于 seq 文件与日志压缩的原子替换；历史日常写入使用 `IndexedHistoryJournal` 增量提交。写入失败显式报告，不降级为截断写入。

## 2026-10-27：接收落库、登录确认和有界重试

- Web outbox 升级至 v3：账号隔离、主键单条查找、到期索引最多每批 32 条；失败项保留，手动重试复用 ID。v1 无可证明账号的待发项保留在原 store，不自动重放；v2 在升级事务内补重试时间。
- Web 每次连接/重连和桌面、Android 生产适配器先查询 `/cluster/owner`。多节点缺失 endpoint 时拒绝任意连接；单节点未配置地址时兼容原目标。owner 重定向不触发登出。WebTransport 的 length-v1 要求先部署支持该协商的后端。
- 桌面收到服务端登录成功后才重放待发并启动心跳。收包进入有上限的串行 IO 队列，旧连接代次和旧账号的数据不能进入当前 UI 或 ACK。Android 仍由其原生传输工作线程串行处理，生产适配器显式注入落库与 owner 发现；fake-driver 测试可以注入离线替身。
- `ReceivedMessagePersistence` 在普通消息接收 ACK 前保存服务端 ID、seq 和附带元数据。UI 的完整消息回调保留这些字段，不再重造 recv_ ID；发送者镜像识别为本人发送，不重复弹本人通知。历史查询游标不由实时单条消息直接推进。
- 原生 Agent 文本累计增量，结束包保留完整文本；Web 重复结束包允许重试最终保存。首次保存失败不能使结束去重阻断后续持久化。
- 写文件与游标错误向上传递；`HistoryWriteQueue` 每批最多尝试三次，保留失败数据，提供 `flush()` / `flushAndClose()`。组件结束时等待 flush；显式清除本地状态仍可取消队列。
- 历史写队列只提交与上次成功保存不同的消息，因此不会反复重写无变化的其他会话。桌面和 Android 共用临时文件、fsync、同目录原子替换；账号 seq 文件/偏好存储互相隔离。

历史文件使用增量日志与元数据索引，首次扫描和压缩仍有 IO 成本。原生接收落库增加磁盘等待，不能用构建/单测宣称吞吐提升。

验证分别覆盖 Web 单测、生产构建与拦截真实网络的浏览器夹具，JVM 测试以及 Android Kotlin 编译。Android 编译时若跳过 JNI 前置任务，只能证明 Kotlin 层，不证明原生库或安装包可用。真实多设备 QUIC、Redis/Kafka 故障恢复和弱网压测需使用隔离环境。


手动重试同样保留原客户端 messageId 和引用信息，不能重新生成 ID。Web 新消息的本地 ID 使用 UUID，避免同一毫秒创建多条消息发生覆盖；服务端为 local_/UUID ID 保留稳定数字主键映射。


## 消息 ID 与服务端主键确认

共享 `model/MessageIdGenerator.kt` 生成 `local_` + UUID，不再使用 32 位 hashCode 和共享计数器。
重试继续使用持久化的原 ID。ACK 的原 messageId 匹配待发请求，可选 serverMessageId（字段 9）提供
真正的历史主键；成功 ACK 显式携带 success，不因发送确认推进完整同步游标。

原生 `MessageIdAliases` 按账号/会话原子保存别名，ACK 处理先持久化别名再完成回调；磁盘失败时
不提前确认发送成功。桌面和 Android 历史存储均按别名转换迟到快照，UI 同步替换 ID 并去重。
别名与该账号历史存储在同一目录生命周期中，尚未增加独立的别名过期清理。
Web 在 IndexedDB 单事务中把乐观记录合并到服务端主键，成功后删除对应账号的 outbox 记录。

服务端重试窗口默认一小时，过期映射保留七天用于拒绝旧请求；窗口过期后应先查历史，再决定是否
以新请求发送，不能依赖手动重试无限期幂等。上线顺序优先更新客户端，再更新服务端映射规则。


## 增量历史、草稿与发送状态

桌面/Android 改用共享 `IndexedHistoryJournal`，仅索引元数据常驻，选中分页才解码消息正文。
仅使用 `.history` 格式，不扫描或迁移旧 JSON，不生成 legacy 备份；旧格式不会被自动删除。
ID 别名也增量追加，确认前先持久化，迟到 UI 快照仍按服务端主键保存。

原生发送状态为 QUEUED、SENDING、ACCEPTED、FAILED；提交输入不等待 ACK，失败按钮仅对
FAILED 出现，重试继续使用原 ID。重启恢复的未确认项允许手动重试，不自动宣称成功。
Web 草稿、引用和提交状态按账号/会话跨布局共享，只有本地消息与 outbox 均提交后清空相应版本。
附件走 `/files`，传输包只包含地址和元数据；切换聊天、退出和取消均核对原异步操作归属。
完整配置、格式与验证边界见 `../../../chat-room/docs/development/JVM-AND-INTERACTION.md`。
